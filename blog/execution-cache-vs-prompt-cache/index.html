Execution Cache vs Prompt Cache — Which Saves More on LLM Costs?

By Mahika Jadhav · May 31, 2026 · 7 min read

Both execution caching and prompt caching reduce your LLM API bill. But they work at completely different levels, apply in different situations, and the savings they produce are not comparable. Using the wrong one for your workload means leaving most of the savings on the table.

Here's the complete breakdown.

What is prompt caching?

Prompt caching (offered by both OpenAI and Anthropic) caches token prefixes at the model level. If the start of your prompt is identical across calls, the provider charges a reduced rate (50–90% discount) for those already-processed tokens.

  • OpenAI: 50% discount on cached input tokens, automatic, requires 1024+ token prefix
  • Anthropic: 90% discount on cached prefix, requires explicit cache_control markers

What it does: Reduces the per-token cost on repeated system prompts and documents included in every call.

What it doesn't do: It still calls the LLM. It still generates output tokens at full price. The model still reasons through the problem from scratch. It helps with long static prefixes — not with repeated reasoning patterns.

What is execution caching?

Execution caching (e.g. Mnemon) caches the complete result of an LLM call or agent run — including the generated output — and replays it on similar future inputs. No LLM call happens at all on a cache hit.

  • Zero input tokens consumed
  • Zero output tokens consumed
  • Zero API call made
  • Result returned in ~2.66ms

When prompt caching wins

  • Long static system prompts (2000+ tokens) reused across many different user messages
  • RAG pipelines that prepend the same large document to every query
  • Few-shot prompts with many fixed examples

If your system prompt is 3,000 tokens and your user message is 50 tokens, prompt caching saves 80%+ on the system prompt portion — significant.

When execution caching wins

  • Recurring workflows — daily reports, scheduled agents, batch classification
  • Similar (but not identical) inputs — the same question asked different ways
  • Multi-step agent chains where you want to cache the full chain result
  • Any workload where the output is the same across similar inputs

Using both together

They're complementary. Enable prompt caching for your static prefix, then add Mnemon for execution-level caching:

import mnemon
mnemon.init()

import anthropic
client = anthropic.Anthropic()

def run_with_both(goal, inputs, *_):
    # Prompt caching: prefix gets 90% discount on tokens
    # Execution caching: entire result skipped on cache hit
    return client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        system=[{"type": "text", "text": LARGE_SYSTEM_PROMPT,
                 "cache_control": {"type": "ephemeral"}}],
        messages=[{"role": "user", "content": inputs["query"]}]
    ).content[0].text

On a cache miss: prompt caching saves 90% on the prefix. On a cache hit: execution caching saves 100% of everything.

For most production agent workloads, execution caching delivers 5–10× more savings than prompt caching alone, because it eliminates the LLM call entirely rather than just discounting input tokens.
