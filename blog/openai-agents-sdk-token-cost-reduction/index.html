I built a customer support triage agent using the OpenAI Agents SDK. It routes tickets, pulls context, and drafts responses. Works great — but after a month in production I noticed the bill was climbing linearly with volume, even though the same ticket types came in every day.

The issue is fundamental: OpenAI Agents SDK runs a fresh agent loop on every invocation. Runner.run() starts from zero each time. The agent re-reasons through the same routing logic, re-evaluates the same tool call patterns, re-produces the same structured outputs — for every ticket, every day.

Where the money goes

OpenAI agent costs accumulate from:

  • Agent loops with multiple tool calls — each step billed separately
  • Repeated handoffs between agents that re-establish the same context
  • Identical or near-identical task types that trigger the same reasoning
  • Scheduled agents running on recurring inputs (reports, digests, alerts)

A multi-agent setup (triage → specialist → responder) can run 5–10 LLM calls per task. On high-volume workloads, that compounds fast.

Why built-in caching doesn't cover this

OpenAI's prompt caching reduces cost on repeated prefixes within a session. It's useful for long system prompts — but it doesn't help when:

  • The user turn changes even slightly between runs
  • Agents use tools that produce slightly different outputs each time
  • You're running across sessions, not within one

You need caching at the execution level — cache what the agent decided, not just what the model said once.

Execution-level caching with Mnemon

Mnemon caches the complete agent execution — tools called, reasoning steps taken, final output — and replays it on similar future inputs without hitting the LLM.

import mnemon
m = mnemon.init()

from openai import OpenAI

client = OpenAI()

def run_triage_agent(goal, inputs, *_):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "You are a support triage agent."},
            {"role": "user", "content": f"{goal}: {inputs['ticket']}"}
        ]
    )
    return response.choices[0].message.content

result = m.run(
    goal="classify and draft response for support ticket",
    inputs={"ticket": "User cannot log in after password reset"},
    generation_fn=run_triage_agent,
)

print(result["output"])         # agent's response
print(result["tokens_saved"])   # tokens saved this run
print(result["cache_level"])    # "system1" | "system2" | "miss"

On the second run with the same or semantically similar ticket type — 2.66ms, zero tokens, zero cost.

Using with the Agents SDK directly

import mnemon
m = mnemon.init()

# Wrap the Runner.run call
from agents import Agent, Runner

support_agent = Agent(
    name="SupportTriage",
    instructions="Classify support tickets and draft initial responses.",
)

def run_agent(goal, inputs, *_):
    result = Runner.run_sync(support_agent, inputs["ticket"])
    return result.final_output

cached_result = m.run(
    goal="triage support ticket",
    inputs={"ticket": "Cannot export data to CSV"},
    generation_fn=run_agent,
)

How matching works

System 1 — Exact match: SHA-256 fingerprint of the full input. Identical inputs return the cached result in ~2.66ms. Zero tokens, zero API cost.

System 2 — Semantic match: "User can't log in" and "login not working" are the same problem. Mnemon matches them semantically and returns the cached execution — paying only for the parts that differ.

System 2 requires embeddings: pip install mnemon-ai[full] or set an OpenAI API key. System 1 alone (exact match) is still valuable for batch or scheduled workloads.
