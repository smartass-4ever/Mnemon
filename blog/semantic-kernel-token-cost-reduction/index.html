Microsoft Semantic Kernel is a mature orchestration framework — well-suited for enterprise AI workflows with its plugin model and planner architecture. I use it for an internal business intelligence assistant that answers recurring analyst questions. The architecture is solid. The Azure OpenAI bill is not.

The problem: Semantic Kernel's kernel invocations are stateless across sessions. Every kernel.invoke() call re-executes the full plugin chain. The planner re-derives the same execution plan. The same analyst question asked twice costs twice.

Where Semantic Kernel costs accumulate

  • Planner re-deriving the same step-by-step plan for recurring request types
  • Semantic functions executing over the same or similar inputs repeatedly
  • Multi-plugin orchestrations with stable patterns across sessions
  • Azure OpenAI-backed workflows where every token has a cost

Execution-level caching with Mnemon

Mnemon wraps Semantic Kernel invocations and caches complete execution results for replay on semantically equivalent future calls.

import asyncio
import mnemon
from semantic_kernel import Kernel
from semantic_kernel.connectors.ai.open_ai import OpenAIChatCompletion

kernel = Kernel()
kernel.add_service(OpenAIChatCompletion(
    service_id="chat",
    ai_model_id="gpt-4o",
))

summarize_fn = kernel.add_function(
    plugin_name="SummaryPlugin",
    function_name="Summarize",
    prompt="Summarize this for an executive: {{$input}}",
    description="Summarizes text for executives",
)

m = mnemon.init()

def run_kernel(goal, inputs, *_):
    return asyncio.run(kernel.invoke(
        summarize_fn,
        input=inputs["text"]
    )).value[0].text

result = m.run(
    goal="executive summary of business report",
    inputs={"text": "Q1 revenue grew 12% YoY driven by enterprise segment..."},
    generation_fn=run_kernel,
)

print(result["output"])        # summary
print(result["tokens_saved"])  # tokens saved this run
print(result["cache_level"])   # "system1" | "system2" | "miss"

Second invocation with the same or similar report: 2.66ms, zero tokens, zero Azure cost.

How matching works

System 1 — Exact match: Identical input → cached result in ~2.66ms.

System 2 — Semantic match: Reports with the same structure but different figures are matched semantically. Only changed content triggers new LLM calls.

System 2 requires embeddings: pip install mnemon-ai[full] or set an API key. Works alongside Azure OpenAI — Mnemon simply intercepts before the API call.
