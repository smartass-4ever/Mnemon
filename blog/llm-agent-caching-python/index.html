LLM Agent Caching in Python — Complete Guide

By Mahika Jadhav · May 31, 2026 · 8 min read

There are four distinct levels at which you can cache LLM agent behavior in Python. Most developers only know about one or two. Understanding all four — and when each applies — is the key to eliminating most of your AI API spend.

The four levels of LLM caching

Level 1: Prompt caching (prefix-level)
Caches repeated prefix tokens within a session. OpenAI and Anthropic both support this. 50–90% discount on cached token portions. Requires 1024+ token static prefix. Doesn't persist across sessions.
Level 2: Response caching (exact match)
Caches the LLM response for an exact input string. LangChain's built-in set_llm_cache does this. Fast and simple — but breaks on any input variation. "weekly report" and "weekly report for May" are different keys.
Level 3: Semantic caching
Uses embeddings to match semantically similar inputs. "How do refunds work?" and "What's your return policy?" hit the same cache. Requires a vector store and embedding calls. Many false positives if not tuned carefully.
Level 4: Execution caching (goal-level)
Caches the complete agent execution — the reasoning, tool calls, and final output — keyed to a goal + inputs pair. Survives sessions, works across frameworks, and enables semantic matching at the intent level rather than the string level. This is what Mnemon does.

Which level should you use?

ScenarioBest cache level
Long static system promptsLevel 1: Prompt caching
Exact same inputs across sessionsLevel 2: Response cache
Similar but not identical inputsLevel 3 or 4
Recurring agent workflowsLevel 4: Execution cache
Scheduled batch jobsLevel 4: Execution cache
Multi-step pipelinesLevel 4: Execution cache

Implementing execution-level caching with Mnemon

Mnemon implements Level 4 caching — it persists execution results across sessions and matches them semantically on future runs.

Auto-patching mode (for LangChain, LangGraph, and compatible frameworks):

import mnemon
mnemon.init()  # patches BaseChatModel.invoke automatically

from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="gpt-4o-mini")

# Your existing code unchanged — caching is transparent
result = llm.invoke("Generate weekly security audit summary")
# Second call with same/similar input: 2.66ms, 0 tokens

Explicit mode (for any Python function):

import mnemon
m = mnemon.init()

import openai
client = openai.OpenAI()

def my_agent_function(goal, inputs, *_):
    # any LLM call — OpenAI, Anthropic, Groq, etc.
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": f"{goal}: {inputs['query']}"}]
    )
    return response.choices[0].message.content

result = m.run(
    goal="classify customer feedback",
    inputs={"query": "The checkout process was confusing and I couldn't find the promo code field"},
    generation_fn=my_agent_function,
)

print(result["output"])           # classification result
print(result["cache_level"])      # "system1" | "system2" | "miss"
print(result["tokens_saved"])     # tokens not sent to LLM
print(result["latency_saved_ms"]) # milliseconds saved

How Mnemon's two-system matching works

System 1 (exact match): SHA-256 hash of the full input. Identical inputs return in ~2.66ms. No embedding calls needed.

System 2 (semantic match): Encodes the goal and inputs as an embedding and finds the closest cached execution. Handles paraphrasing, minor variations, and structurally similar inputs. Only the changed parts get re-generated — you pay for the delta.

System 2 requires embeddings: pip install mnemon-ai[full] or set an OpenAI/Anthropic API key. System 1 alone (exact match) is still valuable and requires no extra dependencies.

Implementing Level 2 and Level 3 caching (for comparison)

LangChain exact-match cache (Level 2):

from langchain.globals import set_llm_cache
from langchain_community.cache import InMemoryCache

set_llm_cache(InMemoryCache())
# Only fires on exact string matches — breaks on any variation

Semantic cache with a vector store (Level 3):

from langchain_community.cache import RedisSemanticCache
from langchain_openai import OpenAIEmbeddings

set_llm_cache(RedisSemanticCache(
    redis_url="redis://localhost:6379",
    embedding=OpenAIEmbeddings()
))
# Better recall — but only caches the LLM response, not the full execution

Choosing the right approach

  • Start with Level 1 (prompt caching) — free if your provider supports it, no code changes needed
  • Add Level 2 (exact response cache) for simple Q&A workloads with stable inputs
  • Use Level 4 (execution cache via Mnemon) for production agents with recurring workflows — this is where the 93% savings come from
  • Level 3 (semantic cache at the response level) is useful but often overlaps with Level 4 — if you're going to cache semantically, do it at the execution level
