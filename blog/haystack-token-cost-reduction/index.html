Haystack from deepset is excellent for building production NLP pipelines — modular, well-tested, and flexible. I run a Haystack RAG pipeline for customer support: retrieves relevant docs, generates answers, routes by category. But the LLM generation step was running full cost on every query, even for questions I'd answered a hundred times.

The issue: Haystack pipelines have no cross-run answer cache. pipeline.run() executes every component fresh. The OpenAIGenerator or AnthropicGenerator at the end of your pipeline doesn't know it produced the same answer last week.

Where Haystack costs accumulate

  • RAG pipelines answering repeated questions over a stable document corpus
  • Generation components producing similar outputs for similar inputs
  • Extractive QA pipelines with recurring question patterns
  • Document summarization over the same or structurally similar content

Execution-level caching with Mnemon

Mnemon wraps Haystack pipeline runs and caches complete execution results for replay on semantically equivalent future queries.

pip install mnemon-ai
import mnemon
from haystack import Pipeline
from haystack.components.builders import PromptBuilder
from haystack.components.generators import OpenAIGenerator

m = mnemon.init()

prompt_template = """
Answer the question based on the context.
Context: {{ context }}
Question: {{ question }}
"""

pipeline = Pipeline()
pipeline.add_component("prompt_builder", PromptBuilder(template=prompt_template))
pipeline.add_component("llm", OpenAIGenerator(model="gpt-4o-mini"))
pipeline.connect("prompt_builder.prompt", "llm.prompt")

def run_pipeline(goal, inputs, *_):
    result = pipeline.run({
        "prompt_builder": {
            "context": inputs["context"],
            "question": inputs["question"],
        }
    })
    return result["llm"]["replies"][0]

cached = m.run(
    goal="answer customer support question from docs",
    inputs={
        "context": "Our refund policy allows returns within 30 days...",
        "question": "How long do I have to return a product?"
    },
    generation_fn=run_pipeline,
)

print(cached["output"])         # generated answer
print(cached["tokens_saved"])   # tokens saved this run
print(cached["cache_level"])    # "system1" | "system2" | "miss"

Second run with the same or similar question: 2.66ms, zero tokens, zero generation cost.

How matching works

System 1 — Exact match: Identical question and context → cached answer in ~2.66ms, zero tokens.

System 2 — Semantic match: "How many days for a return?" and "What's your return window?" match semantically. Cached answer replayed, no LLM call.

System 2 requires embeddings: pip install mnemon-ai[full]. This works alongside Haystack's document store embeddings — they cache different things (document retrieval vs answer generation).

What it doesn't help with

  • Pipelines processing unique documents with no recurring patterns
  • Real-time generation where stale answers are unacceptable
  • First run of any question type — cold start still hits the LLM
