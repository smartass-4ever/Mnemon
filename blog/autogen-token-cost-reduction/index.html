I built an AutoGen pipeline for automated code review — an assistant agent and a critic agent working together to review PRs. Same pattern every day, hundreds of reviews a month. After the first billing cycle I realized: my agents were regenerating the same reasoning on every single call.

This is the core problem with AutoGen at scale: ConversableAgent.generate_reply() is stateless. Every conversation starts fresh. Agents don't remember how they handled structurally identical tasks yesterday. The cost compounds with every run.

The workflows that bleed money

  • Multi-agent pipelines running on a schedule (daily reports, nightly audits)
  • Assistant + critic patterns on similar tasks (code review, content evaluation)
  • Sequential agent chains where early steps repeat across runs
  • Customer-facing agent systems handling common request patterns

Every agent conversation that repeats a prior pattern is money you've already spent — spent again.

The fix

Mnemon patches ConversableAgent.generate_reply() at startup. It intercepts each reply generation, checks if this reasoning has happened before, and serves the cached result if it has.

import mnemon
mnemon.init()   # patches ConversableAgent.generate_reply automatically

# your existing AutoGen code — completely unchanged
from autogen import ConversableAgent

assistant = ConversableAgent(
    name="assistant",
    system_message="You are a helpful code reviewer.",
    llm_config={"model": "claude-sonnet-4-6"},
)

critic = ConversableAgent(
    name="critic",
    system_message="You identify issues in code reviews.",
    llm_config={"model": "claude-sonnet-4-6"},
)

result = assistant.initiate_chat(
    critic,
    message="Review this Python function for security issues: [code here]",
    max_turns=3,
)

No agent restructuring. No conversation flow changes. Your existing code stays exactly as-is.

How it works

System 1 — Exact match: SHA-256 fingerprint of the full message + agent config. Identical inputs on a repeat run return the cached reply in ~2.66ms. Zero tokens.

System 2 — Semantic match: Similar but not identical inputs are matched against stored executions. Only what actually changed gets regenerated. You pay for the diff, not the full conversation.

In multi-turn conversations, Mnemon caches at the reply level — each generate_reply() call is independently cached. A 5-turn conversation with 4 cached turns costs 80% less.

Explicit control for complex pipelines

For pipelines where you want to cache specific agent interactions independently:

import mnemon
from autogen import ConversableAgent

m = mnemon.init()

def run_review_agents(goal, inputs, *_):
    result = assistant.initiate_chat(
        critic,
        message=f"Review for {inputs['pr_id']}: {inputs['code']}",
        max_turns=3,
    )
    return result.summary

review = m.run(
    goal="security code review",
    inputs={"pr_id": "PR-441", "language": "python"},
    generation_fn=run_review_agents,
)

print(review["cache_level"])      # "system1" | "system2" | "miss"
print(review["tokens_saved"])     # tokens saved this run

Multi-agent swarms

The savings multiply with agent count. A 10-agent pipeline where 9 of 10 agents hit the cache saves 90% per run. At 50 agents, Mnemon has demonstrated 62,500 tokens saved in a single burst — 0 LLM calls, 0.18 seconds total.

What it doesn't help with

  • Agents handling genuinely novel inputs every time
  • Conversations requiring real-time context
  • Cold starts — first execution of any goal still hits the LLM
