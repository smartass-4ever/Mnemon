Your OpenAI bill is growing linearly with usage. You've tried switching to cheaper models, shortening prompts, and batching requests. The bill is still climbing. Here's what actually moves the needle — ranked by impact.

Technique 1: Cache execution results (biggest win)

Most production AI workloads have significant repetition. The same agent processes the same types of inputs daily. The same questions come in over and over. The same workflows run on a schedule.

Every repeated run that hits the OpenAI API is wasted money. Execution caching intercepts the call, checks if this problem has been solved before, and returns the cached result in milliseconds — at zero token cost.

import mnemon
m = mnemon.init()

from openai import OpenAI
client = OpenAI()

def classify_ticket(goal, inputs, *_):
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "Classify support tickets by category and priority."},
            {"role": "user", "content": inputs["ticket"]}
        ]
    )
    return response.choices[0].message.content

result = m.run(
    goal="classify support ticket",
    inputs={"ticket": "User cannot log in after password reset"},
    generation_fn=classify_ticket,
)
# Second identical or similar ticket: 2.66ms · 0 tokens · $0.00

Impact: 93% cost reduction on recurring workloads. This alone eliminates most of the bill for scheduled, batch, or FAQ-style applications.

Technique 2: Use the right model for the task

GPT-4o costs ~15× more per token than GPT-4o-mini. Most tasks don't need that power.

Technique 3: Enable prompt caching

OpenAI charges 50% less for tokens that appear in cached prefixes. If your system prompt is long and static, this fires automatically — but only within a session window.

# Ensure your system prompt is at the start and unchanged across calls
# OpenAI auto-caches after the first call if the prefix is 1024+ tokens
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": LONG_STATIC_SYSTEM_PROMPT},  # cached after first call
        {"role": "user", "content": user_message}  # varies each call
    ]
)

Impact: 50% reduction on system prompt tokens. Only helps if your system prompts are long (1024+ tokens) and reused across calls in the same session.

Technique 4: Reduce output tokens

Output tokens cost 3–4× more than input tokens. Shorten your outputs explicitly:

# Bad — LLM writes a paragraph when you need two words
"What is the sentiment of this review?"

# Good — constrain the output
"Classify the sentiment of this review. Reply with exactly one word: positive, negative, or neutral."

Impact: 20–60% cost reduction depending on how verbose your current prompts are.

Technique 5: Batch API for offline workloads

OpenAI's Batch API runs requests asynchronously within 24 hours at 50% of normal price. If your workload doesn't need real-time responses, this is free money.

from openai import OpenAI
client = OpenAI()

batch = client.batches.create(
    input_file_id=file_id,
    endpoint="/v1/chat/completions",
    completion_window="24h"
)

Impact: 50% across the board for any non-real-time workload.
