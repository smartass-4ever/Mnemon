How to Cache LangChain Agent Responses Between Sessions

By Mahika Jadhav · May 31, 2026 · 6 min read

You've set up LangChain's cache. It works great — within a single run. But restart your script, redeploy your service, or schedule it for tomorrow morning, and the cache is gone. You're back to paying full price on every run.

This is one of the most common frustrations with LangChain caching. Here's why it happens and three ways to fix it, from simplest to most powerful.

Why LangChain's default cache doesn't persist

LangChain's InMemoryCache stores responses in a Python dictionary — it lives only as long as the process. It's useful for deduplication within a single script run but provides zero benefit across sessions.

# This cache dies when the script ends
from langchain.globals import set_llm_cache
from langchain_community.cache import InMemoryCache
set_llm_cache(InMemoryCache())  # gone on restart

Option 1: SQLite cache (simplest persistent option)

LangChain ships with a SQLite-backed cache that persists to disk:

from langchain.globals import set_llm_cache
from langchain_community.cache import SQLiteCache

set_llm_cache(SQLiteCache(database_path=".langchain.db"))

# Now responses survive restarts — but only exact string matches

Limitation: Only matches exact input strings. "weekly report for Acme" and "Acme Corp weekly report" are different cache keys — both hit the LLM.

Option 2: Redis cache (distributed, exact match)

from langchain_community.cache import RedisCache
import redis

set_llm_cache(RedisCache(redis_=redis.Redis.from_url("redis://localhost:6379")))
# Persists across restarts, shareable across instances
# Still exact-match only

Option 3: Execution-level cache (persistent + semantic, recommended)

Mnemon persists complete agent executions to SQLite — survives restarts, deployments, and reschedules — and matches semantically similar inputs, not just exact strings.

pip install mnemon-ai
import mnemon
mnemon.init()  # patches BaseChatModel, persists to local SQLite

from langchain_anthropic import ChatAnthropic

llm = ChatAnthropic(model="claude-sonnet-4-6")

# Run 1 — Monday morning
response = llm.invoke("Generate weekly fintech market summary")
# Hits LLM, caches the execution to disk

# Run 2 — Tuesday morning (new process, new session)
response = llm.invoke("Generate weekly fintech market summary")
# Returns cached result in 2.66ms — zero tokens, $0.00

# Run 3 — Wednesday morning (slightly different phrasing)
response = llm.invoke("Weekly fintech sector market summary")
# System 2 semantic match — still returns cached result
Mnemon's cache is stored at ~/.mnemon/ by default — persists across all restarts and redeployments. Override with MNEMON_CACHE_DIR.

For scheduled agents

If you're running LangChain on a schedule (cron, Airflow, GitHub Actions), Mnemon is the cleanest solution — no external dependencies, no Redis to manage, and the cache grows smarter over time as it accumulates executions.

# cron: runs every day at 9am
import mnemon
mnemon.init()

from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="gpt-4o-mini")

result = llm.invoke("Daily security audit summary for prod environment")
# Day 1: hits OpenAI
# Day 2 onward: 2.66ms, $0.00
