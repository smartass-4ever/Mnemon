LangGraph Persistent Cache Across Runs — How to Stop Re-Paying Every Invocation

By Mahika Jadhav · May 31, 2026 · 6 min read

LangGraph's checkpointer gives you persistence within a thread — you can resume a conversation or workflow mid-flight. But across separate invocations with the same or similar inputs, LangGraph starts the LLM work from scratch every time. There's no cross-invocation execution cache built in.

If your graph processes recurring workflows — the same type of input arriving daily, weekly, or on a schedule — you're paying for the same LLM reasoning repeatedly.

The difference: checkpointer vs execution cache

  • LangGraph checkpointer: Persists state within a thread so you can resume an interrupted run. Doesn't help when you invoke the graph fresh on a new but similar input.
  • Execution cache (Mnemon): Persists the result of a graph invocation so that similar future invocations skip the LLM entirely.

Both are useful. They solve different problems.

Adding persistent execution caching to LangGraph

import mnemon
mnemon.init()  # patches BaseChatModel — all LangGraph LLM nodes cached automatically

from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from typing import TypedDict

llm = ChatOpenAI(model="gpt-4o-mini")

class State(TypedDict):
    input: str
    analysis: str
    summary: str

def analyze_node(state: State) -> State:
    result = llm.invoke(f"Analyze this: {state['input']}")
    return {"analysis": result.content}

def summarize_node(state: State) -> State:
    result = llm.invoke(f"Summarize: {state['analysis']}")
    return {"summary": result.content}

graph = StateGraph(State)
graph.add_node("analyze", analyze_node)
graph.add_node("summarize", summarize_node)
graph.set_entry_point("analyze")
graph.add_edge("analyze", "summarize")
graph.add_edge("summarize", END)
app = graph.compile()

# Invocation 1 — hits LLM, caches both node results
result1 = app.invoke({"input": "Q1 sales report: revenue up 12%, EMEA weak"})

# Invocation 2 (new process, new session, same input)
result2 = app.invoke({"input": "Q1 sales report: revenue up 12%, EMEA weak"})
# 2.66ms · 0 tokens · $0.00 — both nodes served from cache

Explicit wrapping for full control

import mnemon
m = mnemon.init()

def run_graph(goal, inputs, *_):
    return app.invoke({"input": inputs["report"]})["summary"]

result = m.run(
    goal="weekly sales analysis and executive summary",
    inputs={"report": "Q2 revenue: $4.2M, +8% QoQ, enterprise segment leading"},
    generation_fn=run_graph,
)

print(result["cache_level"])      # "system1" | "system2" | "miss"
print(result["tokens_saved"])
print(result["latency_saved_ms"])
The explicit m.run() wrapper lets Mnemon match semantically similar inputs — "Q2 revenue report" and "Q2 sales summary" hit the same cache entry via System 2.
