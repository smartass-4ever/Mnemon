How I Cut My LiteLLM API Costs by 93% with One Import

By Mahika Jadhav · May 31, 2026 · 5 min read

LiteLLM is excellent for multi-provider LLM routing — one interface for OpenAI, Anthropic, Gemini, Bedrock, and 100+ other providers. It handles fallbacks, load balancing, and spend tracking. What it doesn't do: execution caching. Every litellm.completion() call routes to a provider and bills you — even for inputs you've processed before.

LiteLLM routes your calls. Mnemon caches the results. Together they eliminate 93% of costs on recurring workloads.

Adding execution caching to LiteLLM

pip install mnemon-ai
import mnemon
m = mnemon.init()

import litellm

def run_litellm(goal, inputs, *_):
    response = litellm.completion(
        model="gpt-4o-mini",  # or "claude-haiku-4-5", "gemini/gemini-1.5-flash", etc.
        messages=[{"role": "user", "content": f"{goal}: {inputs['text']}"}]
    )
    return response.choices[0].message.content

result = m.run(
    goal="classify customer feedback sentiment and category",
    inputs={"text": "The new dashboard is confusing, I can't find the export button"},
    generation_fn=run_litellm,
)

print(result["output"])         # classification result
print(result["tokens_saved"])   # tokens not sent to any provider
print(result["cache_level"])    # "system1" | "system2" | "miss"

Second call with same or similar feedback: 2.66ms, zero provider tokens, $0.00.

With LiteLLM fallbacks

import mnemon
m = mnemon.init()

def run_with_fallback(goal, inputs, *_):
    # LiteLLM handles fallbacks — Mnemon caches the result regardless of which provider answered
    response = litellm.completion(
        model="gpt-4o",
        fallbacks=["claude-sonnet-4-6", "gemini/gemini-1.5-pro"],
        messages=[{"role": "user", "content": inputs["query"]}]
    )
    return response.choices[0].message.content

result = m.run(
    goal="generate weekly engineering summary",
    inputs={"query": "Summarize PRs, incidents, and deploy frequency for this week"},
    generation_fn=run_with_fallback,
)
# Cache hit: skips LiteLLM entirely — no provider called, no fallback needed

With LangChain + LiteLLM

import mnemon
mnemon.init()  # auto-patches BaseChatModel

from langchain_community.chat_models import ChatLiteLLM

llm = ChatLiteLLM(model="gpt-4o-mini")
response = llm.invoke("Analyze weekly sales metrics")
# cache hit → 2.66ms, 0 tokens across all providers

Why this pairing works well

LiteLLM's strength is routing and fallbacks — it ensures your calls get answered reliably. Mnemon's strength is remembering the answers and not asking again. On a cache hit, LiteLLM's routing logic is never invoked — you save both the token cost and the routing overhead.
