Instructor is the go-to library for structured LLM outputs — Pydantic validation, automatic retries, clean API. I use it for a data enrichment pipeline that classifies and extracts structured data from incoming records. Clean results. But high volume means high costs when the same record types come in repeatedly.

The problem: Instructor has no execution cache across calls. Every client.chat.completions.create() with response_model hits the LLM fresh. If you're extracting the same category of data — job postings, invoices, product descriptions — you're paying full price every single time.

Where Instructor costs accumulate

  • Classification pipelines processing recurring input categories
  • Entity extraction over structurally similar documents
  • Data enrichment workflows with repeating record types
  • Validation-heavy extractions where retries compound the cost

Execution-level caching with Mnemon

Mnemon wraps Instructor calls and caches complete extraction results — including the Pydantic-validated output — for replay on semantically equivalent future inputs.

pip install mnemon-ai
import instructor
import openai
import mnemon
from pydantic import BaseModel

client = instructor.from_openai(openai.OpenAI())
m = mnemon.init()

class JobPosting(BaseModel):
    title: str
    company: str
    required_skills: list[str]
    seniority: str
    remote: bool

def extract_job(goal, inputs, *_):
    result = client.chat.completions.create(
        model="gpt-4o-mini",
        response_model=JobPosting,
        messages=[{
            "role": "user",
            "content": f"Extract structured data from this job posting:\n{inputs['text']}"
        }],
    )
    return result.model_dump_json()

cached = m.run(
    goal="extract structured job posting data",
    inputs={"text": "Senior Python Engineer at Acme Corp. Remote OK. Skills: Python, FastAPI, AWS..."},
    generation_fn=extract_job,
)

print(cached["output"])         # JSON-serialized JobPosting
print(cached["tokens_saved"])   # tokens saved this run
print(cached["cache_level"])    # "system1" | "system2" | "miss"

Second posting of the same type: 2.66ms, zero tokens, zero extraction cost.

How matching works

System 1 — Exact match: Identical input text → cached extraction in ~2.66ms.

System 2 — Semantic match: Two senior Python engineer postings from different companies extract to the same schema. Mnemon matches them and returns the cached result, only updating fields that actually differ.

System 2 requires embeddings: pip install mnemon-ai[full]. Particularly valuable for Instructor workflows where you're processing many structurally similar documents.
