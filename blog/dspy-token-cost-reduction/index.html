DSPy is powerful for optimizing LLM program logic — you compile prompts, optimize with optimizers, and get reliable structured outputs. I use it for a multi-hop reasoning pipeline over technical documentation. The compiled program is excellent. The production bill, less so.

The problem: every program() forward call re-executes the full pipeline. DSPy has a development-time cache (DSPY_CACHEDIR) for speeding up optimization runs, but this doesn't carry into production. In deployment, every query triggers the LLM chain from scratch.

Where DSPy production costs accumulate

  • Multi-hop reasoning chains where early hops are stable across similar queries
  • Chain-of-Thought modules answering recurring question patterns
  • ReAct loops that repeatedly arrive at the same tool-call decisions
  • Classify or extract modules processing similar input categories

Execution-level caching with Mnemon

Mnemon wraps DSPy program calls and caches complete execution results for replay on semantically similar future inputs.

pip install mnemon-ai
import dspy
import mnemon

dspy.configure(lm=dspy.LM("openai/gpt-4o-mini"))
m = mnemon.init()

class TechQA(dspy.Signature):
    """Answer technical questions with step-by-step reasoning."""
    question: str = dspy.InputField()
    answer: str = dspy.OutputField()
    reasoning: str = dspy.OutputField()

cot = dspy.ChainOfThought(TechQA)

def run_program(goal, inputs, *_):
    result = cot(question=inputs["question"])
    return f"{result.answer}\n\nReasoning: {result.reasoning}"

cached = m.run(
    goal="answer technical question with reasoning",
    inputs={"question": "What causes memory leaks in Python async code?"},
    generation_fn=run_program,
)

print(cached["output"])         # answer + reasoning
print(cached["tokens_saved"])   # tokens saved this run
print(cached["cache_level"])    # "system1" | "system2" | "miss"

Second query with the same or semantically similar question: 2.66ms, zero tokens, zero cost.

With compiled/optimized programs

import dspy
import mnemon

m = mnemon.init()

# Load your compiled program
compiled_program = dspy.load("./optimized_qa.json")

def run_compiled(goal, inputs, *_):
    result = compiled_program(question=inputs["question"])
    return result.answer

cached = m.run(
    goal="technical support answer",
    inputs={"question": "How do I configure connection pooling in SQLAlchemy?"},
    generation_fn=run_compiled,
)

How matching works

System 1 — Exact match: Identical input text → cached result in ~2.66ms, zero tokens.

System 2 — Semantic match: "How do I fix a memory leak?" and "Why is my Python process growing in memory?" are the same debugging intent. Mnemon matches them and returns the cached answer.

System 2 requires embeddings: pip install mnemon-ai[full] or set an API key. This complements DSPy's optimization cache — DSPy caches during compilation, Mnemon caches during production inference.

What it doesn't help with

  • Programs where every input is genuinely unique
  • Real-time inference where you need fresh LLM outputs always
  • Cold starts — first execution of any query type still hits the LLM
